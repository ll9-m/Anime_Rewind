# 番忆 · Anime Rewind

> 把童年看过的动画建成一座私人档案馆。记录片库、重看次数、童年编年史与语录。
> **数据全部留在本机**，没有账号，没有服务器，关掉页面也不会丢。

单文件交付：`anime-rewind.html`（约 1.1 MB，含全部 CSS/JS 与内联配图）。
原生 HTML/CSS/JS，**零构建、零依赖、零后端** —— 双击就能用，也可以直接丢进任意静态托管。

在线体验：<https://anime-rewind.app.workbuddy.host/>

> 📄 [`番忆-需求文档.md`](番忆-需求文档.md) —— 完整需求与验收依据（455 行）。
> 想知道「为什么这么做」而不是「做了什么」，看这份。

## 快速开始

```
# 方式一：直接打开（最简单）
start anime-rewind.html          # Windows
open  anime-rewind.html          # macOS

# 方式二：起个本地服务（推荐，file:// 下部分浏览器能力受限）
python -m http.server 8080       # 然后访问 http://localhost:8080/anime-rewind.html
```

> **为什么推荐本地服务**：`file://` 打开时 origin 为 `null`，IndexedDB 在部分
> Chromium 环境不可用，会自动降级到 localStorage（容量约 5MB，4MB 能写、5MB 会失败）。
> 功能不受影响，只是容量小一些。想用完整存储就起个服务。

**首次使用**：首页 → 右上「添加新番」→ 搜索（Bangumi / AniList）→ 加入片库。

## 部署

项目是纯静态单文件，丢进任何静态托管都能跑，不需要构建。

| 方式 | 怎么做 | 备注 |
|---|---|---|
| **GitHub Pages（自动）** | 什么都不用做 —— 推 `master` 即由 `.github/workflows/static.yml` 自动部署 | 需在 Settings → Pages 把 Source 选为 **GitHub Actions** |
| **GitHub Pages（手动）** | Settings → Pages → Source 选 `master` / 根目录 → 保存 | 不走 Actions 时用这个 |
| **Netlify / Vercel / Cloudflare Pages** | 拖整个目录上传，或连仓库选 `master` 分支 | 无需构建命令，输出目录就是仓库根 |
| **在线体验** | <https://anime-rewind.app.workbuddy.host/> | 已托管的实例，可直接访问 |

> **Source 一定要选 GitHub Actions**：官方模板生成的 workflow 是走 Actions 部署的，
> 若Source 选了 `master` 分支，两套机制会互相覆盖，行为不稳定。

### 自动部署只上传四个文件

workflow 的 `path:` 是显式清单，不是整个仓库：

| 文件 | 作用 |
|---|---|
| `anime-rewind.html` | 主应用（1.1MB 单文件） |
| `index.html` | 站点根入口，Pages 只解析这个文件名 |
| `LICENSE` | CC BY-NC 4.0 全文，许可要求随作品分发 |
| `.nojekyll` | 不走 Jekyll 构建 |

原本写的是 `path: '.'`（整个仓库），那会把 `tools/` 下 30+ 个测试脚本、
`.workbuddy/memory/` 的内部工作记录和需求文档一并公开到线上——站点目录等于一个可浏览的源码仓，
而且每次改测试脚本都会触发一次无意义的重新部署（artifact 变了但页面没变）。

> 校验这份清单：`node tools/verify-workflow.js`（16 项）。清单是明文字符串，
> 文件被改名时 GitHub 不会报错，只会在部署日志里留下一个 404 —— 这个脚本把「声明」和磁盘实际对齐。

### 关于 `index.html`

主文件叫 `anime-rewind.html`（本地双击、开具名文件都用这个名），而**静态托管的站点根路径只解析 `index.html`**。缺了它，从根地址进来必然是「404 未找到文件」——哪怕主文件好好躺在仓库里。

所以仓库根目录放了一个跳转页而不是把主文件复制成 `index.html`：

- **不复制**：复制会产生两份 1.1MB 独立副本，此后每次改代码都要记得同步两处，漏同步就产生两个行为不一致的版本。
- **只做路由**：跳转用相对路径 + `location.replace`。相对路径在「部署到域名根」和「部署到仓库子路径 `/Anime_Rewind/`」两种情形下都成立；`replace` 不往浏览器历史里塞一条，用户按返回键不会被弹回来。禁用 JS 的场景留了 `<noscript>` 兜底链接。
- 跳转页同样带署名与许可声明，符合 CC BY-NC 4.0 的署名要求。

`.nojekyll` 是配套的：Jekyll 默认会把下划线开头的文件当特殊文件处理，禁用掉可避免线上取不到资源。

> 想验证根路径确实通了：`node tools/verify-entry.js`。它起本地静态服务对齐托管的根解析规则，
> 实测 9 项——含**反向验证**：把 `index.html` 挪走，根路径必须回404。
> 这一步是必要的，否则「检查通过」可能只是因为检查根本没生效。
> 必须在 `http://` 源下验：`file://` 的origin 为 null，IndexedDB 会降级到 localStorage，线上不会。

## 值得一说的几个设计

### 系列归类
「每部动画都不止一部 / 一季」—— 第一季、第二季、剧场版、续作应该聚在一起。
导入或编辑时归到某个系列，没有就落「默认系列」。

- 卡片正面显示系列徽标（**未归类不挂标签** —— 满屏「默认系列」等于没信息）
- 筛选器只列出真有作品的系列，并显示数量
- 排序选「系列（归拢同一部）」，同系列内按首播年自动挨在一起
- 详情页有「同系列其他作品」，点一下直接跳过去
- 搜索时**系列名也参与匹配**（你记得「这是那个系列里的」，却想不起具体某一季的片名时）
- 导入备份时按**名称**重映射（备份里的 id 是源机器的，跨机直接搬一条都对不上）

### 卡片翻面
封面墙是 3D 翻转卡：鼠标移上去翻面看资料与操作。

- 电脑（能 hover）：移上去自动翻
- 手机 / 平板（无 hover）：**点第一下卡片翻面看资料，再点一下进详情**

两套路径由 `cardFlipByHover()` 分流。所有 `:hover` 交互规则都包在
`@media (hover:hover)` 里 —— 移动端浏览器点完会留下「粘住」的 `:hover`，
不隔离的话静止态卡片会因为残留 hover 把 `pointer-events` 交给背面，手指再点正面就点不动。

### 四 UI 套系
四套皮肤共用同一份布局与配色令牌，靠 `[data-skin]` 覆盖「形状」：

- `archive` 档案馆 —— 圆角、发丝线、柔和阴影（默认）
- `pixel` 像素 8-bit —— 0 圆角、3px 硬边框、像素字体、抖动渐变
- `holo` 科技全息 —— 全息描边、发光、故障按钮、扫描线
- `tv` TV 影院 —— 电视端形态，几何取自 [Izuko_TV](https://github.com/ll9-m/izuko-tv)

新增皮肤零布局改动，四套样式也不会互相污染（`tools/test-tv-skin.js` 有 CSS 泄漏扫描，
覆盖既有类名的规则必须挂 `[data-skin="tv"]` 前缀）。

#### TV 影院模式

参考 Izuko_TV 的电视端改版。**只在 `tv` 套系下生效**，其余三套维持原样 ——
桌面浏览器里纵向网格才是对的，横滑卡行在没有「左右走」肌肉记忆的鼠标下是反模式。

几何全部取自 Izuko_TV 的实际值，不是自拟的：

| 项目 | 值 | 出处 |
|---|---|---|
| 侧栏收起态宽 | 48px | `TvNavigationSideRail` |
| 展开遮罩 | 180px 右缘羽化 | 同上 |
| 海报卡最小宽 | 118px | `TvPosterWall` |
| 列数 | `floor((可用宽 + 间距) / (最小卡宽 + 间距))` | 同上（1080p 848px 内容区 → 6 列） |
| 番名区 | `min-height: calc(2 * 1.5em)`（一行番名也占两行高，换焦点不跳） | 同上 |
| 深灰底 / 浅灰底 | `#2C2C2E` / `#BFC4C7`（不用纯黑纯白，电视上刺眼且分不出层次） | 同上 |
| 剧集卡 | 256×144（16:9）、圆角 6、进度条 3px、已看压暗 .45 | `FocusEpisodesSection` |
| 剧照压暗 | 卡底 `.85` → 半高处全透明 | `EPISODE_STILL_SCRIM_*` |

**片库多了「卡行」视图**（该套系下才出现）：`继续观看` 置顶行 + 各系列行 + 兜底行。
行内横滑，行尾挂「更多」玻璃卡，点开把那一组摊成网格。

- 继续观看的口径：`在看`状态 或 有进度未看完，按最近更新倒序
- 置顶行里出现过的作品不再在系列行里重复占位（一屏两张一样的卡会被当成 bug）

**详情页多了剧集卡行**：16:9 卡 + 集号 + 3px 进度条，四态区分「已看 / 在播 / 下一集 / 未看」。
点一张即把该集设为当前集，与播放器面板的「看到第几集」写同一个字段。

> ⚠️ **已知降级**：本项目没有逐集剧照与集名数据（抓取侧只存作品级封面与总集数），
> 所以剧集卡的剧照位用的是**作品封面**，不是真剧照。渲染成好像有剧照的样子只会误导用户。
> 要补真数据得动抓取侧（`EpisodeInfo.still` / `name`），那是另一次改动。

### 其他
- **三主题**：深色 / 浅色 / 液态玻璃；**六强调色**；**两档密度**
- **开机音效**：WebAudio 合成，无音频文件
- **进度自动算状态**：看过 ≥100% 自动标「看过」，1~99% 为「在看」，也可手动指定
- **重看轮次**：首次 = 1，重看一次后新增 = 2，取现有最大值 +1，弹窗里可手动修正
- **CSV 批量导入语录**：表头智能映射，重复自动跳过
- **放映厅外部播放器**：支持 B 站（自动解析 season）与通用 URL，不会播放时提供跳转官方

### 播放源：多线路 + 手动选源

一部作品可以存**多条线路**（`sources` 数组 + `activeSourceId`）。

**默认线路有两个入口可改，都不用先播放**：

- **放映厅详情页**：播放源面板里直接列出全部线路，点一下设为使用中，双击顺手起播。正在播的时候点线路会立刻换源（保留进度语义），不会从头开始。
- **播放源台账页**：每行一个靶心按钮「设为使用中」，工具条上还有「设为使用中」批量操作（每部作品取勾选的第一条）。当前线路那行显示「使用中」徽标而不是按钮 —— 不给点了没用的操作。

> 之前只有播放器控制条上的「选源」入口，等于要求用户先起播一次才能改默认线路。
> 但「我下次就想看这条」是保存时的决策，不该被播放动作卡住。

**自动选源**在手动指定之前生效，直译 [Animeko](https://github.com/animeko/Animeko)：

- **三态筛选**：被排除的资源不丢弃，携带原因（集数不匹配 / 无字幕 / 字幕形态不支持 / 网址无效 / 已停用 / 已失效）排到末尾
- **四层 DFS 偏好**：分辨率 → 字幕语言 → 字幕组 → 线路，四层字典序，不是加权求和
- **分阶段自动选源**：记忆线路 → tier≤0 → 精确匹配 → 全部候选

> 关键坑：字幕组匹配不到时**不下降到更差的字幕语言**；
> 质量优先而非大小优先（4K 体积是 1080P 十倍，掺进评分成噪音）。

> 第二条关键坑：**手动指定允许指向已停用/已失效的线路** ——
> 「我就是要用这条」是用户的判断，算法不该替他改掉。
> 但界面必须显式说「它不会被自动选中」，否则用户以为设了就等于下次一定播它。

**播放器双轨**：直链（mp4/webm/m4v/ogg）走原生 `<video>`，其余站点沿用 iframe。
理由是 iframe 里读不到 `currentTime` —— 续播、倍速、片尾自动下一集都要时间轴。

键盘语义照 `TvEpisodeScreen`：←→ 5 秒 / ↑↓ 唤控制层 / F 全屏 /
空格两段（轻点启停、按住临时加速，250ms 阈值）。长按加速用固定 90ms 定时器推进
（不用 keydown 的 repeat 事件，系统重复间隔在不同机器上 30–200ms 不等）。

> **硬约束**：Izuko_TV 的自动选源靠原生 HTTP 客户端绕过跨域，浏览器做不到 ——
> 第三方站点的 m3u8 与搜索页都会被 CORS 拦掉。网页端的「自动搜源」只能是
> 用户自带源表 + 手动直链。BT / 夸克网盘在网页端完全做不到（P2P），必须放弃。

### 播放源管理：跨作品台账

逐部作品去看线路有两个绕不过的问题：**失效是跨作品的公共事实**（同一个站点挂掉时库里可能有十几条线路一起失效，逐部去发现必然漏掉一半）；**删除与停用是批量决策**（「把检测不通的都清掉」在逐部视角下无法表达）。

所以把 `a.sources` 摊平成一张全局台账 —— 每一项是 `{ anime, source }`，动它就是动那部作品的那条线路。**台账是视图，不是第二份存储。**

- **七格汇总条**：线路总数 / 探测可达 / 已标记失效 / 访问不通 / 未检测 / 已停用 / 作品尚无片源
- **探测**：`fetch(..., { mode:"no-cors" })`。浏览器对第三方站点既读不到状态码也读不到正文，唯一能确定的是「响应回来了没有」
- **逐条操作**：探测 / **设为使用中** / 编辑 / 停用启用 / 标记失效 / 新标签打开 / 删除。已是使用中的那行显示徽标而不是按钮
- **批量操作**：勾选后停用 / 启用 / **设为使用中** / 标记失效 / 删除；另有「去重」（同作品内网址与集数完全相同的多余项，每组保留最早添加的那条）
- **筛选**：按状态（使用中 / 已失效 / 未检测 / 已停用 / 无播放源）、按片名 / 线路名 / 网址 / 站点 / 备注搜
- **排序**：按作品 / 按状态（**问题排最前**）/ 按添加时间 / 按站点
- **逐条编辑**：网址、名称、集数、分辨率、优先级、字幕形态与语言、备注
- **待办行**：筛「无播放源」时，那一行给的是「去添加」按钮而不是线路操作组

**「管理」必须真的管用**：停用与标记失效会同步进选源算法的三态筛选（`filterSources` 排除，附带原因文案），`activeSourceOf` 也会跳过它们 —— 否则用户标了失效、回到放映厅它照旧自动起播，管理就成了假动作。

> **三种「不确定」不许被画成「确定」**：
> 「未检测」不等于「可用」；探测失败只归入 `blocked`（被拒绝 / 不确定），**绝不写「已失效」** —— 失效是用户的判断，不是探测器的判断。批量探测也不会覆盖用户手动标的失效，一次网络波动不该抹掉人的结论。

两个入口：侧栏导航，或放映厅详情页播放源面板的「播放源管理」按钮（跳转时预填该作品片名，省得在几十行里翻找）。

> 台账的所有写操作刻意走 `Repo.put` 而非 `saveAnime`：后者会 `touch()` 改 `updatedAt`，
> 于是「整理一次线路」就能把老作品顶到「最近添加」最前面。播放记录 `lastUsedAt` 同理。

## 数据

**全部在本机，没有一个字节离开你的浏览器。**

| 内容 | 位置 |
|---|---|
| 作品 / 语录 / 状态 / 系列 / 图片 | IndexedDB（`anime-rewind` v2），降级 localStorage |
| 设置（含自定义荣誉） | localStorage `ar.settings.v1` |

IndexedDB 表：`anime` / `quotes` / `statuses` / `series` / `assets`。

**备份**：设置 → 数据 → 导出数据，得到一个 JSON（含作品、语录、状态、系列、设置，
可选是否带上背景图）。导入时可以选择跳过 / 智能合并 / 覆盖三种去重模式，
会先给一份预览报告（新增多少、跳过多少、重复多少）。系列按名称重映射，
跨机器导入不会掉回默认系列。

同分区还有「恢复内置语录包」（补回被遗漏的内置语录，不删自建的）、存储占用查看、
清空全部数据。

### 为什么有些验证必须开真浏览器

`jsdom` 不做布局、不渲染 3D：`getBoundingClientRect` 一律返回 0，
`backface-visibility` / `perspective` 完全不生效。
于是「元素被 `overflow:hidden` 裁掉一半」「3D 翻转后两个面同时不可见」
这类故障在单测里永远是绿的 —— DOM 完好、样式规则齐全、断言全过。

`tools/verify-tv-layout.js` 用 headless Edge + CDP 量真实几何，
并对截图像素做统计（`inkRatio`）。它的两条判据值得记住：

- **像素统计的阈值必须从实际底色亮度推出**，不能写死绝对值。
  写死 `46` 而侧栏底色亮度是 `52` 时，整块背景被算成「有内容」，
  收起态恒为 `ink=1` —— 一个恒真的假红。
- **「画面非空」要用相对判据**（翻面后必须明显比翻面前「有东西」），
  不能对正面用绝对阈值：测试数据常无封面，正面本来就是暗的。

`tools/verify-ledger.js` 验台账页时补了第三条：

- **测试自己制造的前提要先排除干净**。本轮有五条断言先后失败，
  原因全是「前面几步把某条线路停用了，而后面又写死 id 去取它」——
  测的是前提不是行为。这类失败不修测试，等于把真信号一起埋掉。
  修法是让断言按当前实际状态去取对象（`sourceUsable(r.source)`），
  并把「哪几行被动过」显式记下来。

### 委托监听器：整表重渲的页面必须只挂一次

台账页的按钮全是 `data-act` 委托到 `#view` 上的。修吐司刷屏时
挖出一条更普适的规律，值得单列：

`rerenderLedger()` 走的是 `rerender → renderRoute → page.render(view)`，
而 **`#view` 这个节点本身从不替换、只换 `innerHTML`**。
所以每次重渲染都往同一个 `root` 上再挂一遍监听器 ——
第三次点按钮就触发三次，批量操作会连着写三次库。
症状是「吐司刷屏」，看起来像渲染有问题，实际是监听器叠了 N 层。
反向验证时一次点击弹出了 **90 个**吐司。

修法是 `root.dataset` 打幂等标记。但**只挂一次之后，闭包里捕获的
`all` / `rows` / `dupes` 就成了首次渲染的快照**，增删改之后全是旧的，
必须改成每次现取 —— 否则去重会拿上一轮的旧列表二次删除。

判据也重写了：「一次操作弹几个吐司」比「功能有没有生效」灵敏得多。
`box.checked === true` 在这个 bug 下**依然是 true**
（状态是对的，坏的是重渲后的属性回填），只有数吐司个数才抓得到。

### 勾号要量像素，不能只量状态

`input[type=checkbox]` 用了 `appearance:none` + `::after` 画对角线。
断言只写 `box.checked === true` 的话，勾号**画没画出来、有多粗、
在浅色套系下和不和底色混成一片**，全部测不出来。
`tools/verify-pick-contrast.js` 遍历四套 UI × 明暗主题，
每种组合都量勾号的宽高、描边宽度、勾色与底色的差异，
再把截图塞回页面用 `OffscreenCanvas` 读像素 ——
**量化后至少 3 种颜色**才算勾真的画出来了
（抗锯齿的斜边会渲出过渡色，只有 2 种色说明勾压根没画）。

刻意没装 `pngjs`：为一个断言新增依赖不划算，
`OffscreenCanvas` 是浏览器自带的，判据一样成立。

### 三条与「就地重渲」有关的坑

线路列表要能换完立刻换下一条，所以用的是**就地重画那块 DOM**而不是整页重渲
（整页重渲会顺手把正在播的播放器销毁）。这一决定牵出三个必须一起处理的点：

**一、事件必须委托到常驻容器。** 逐元素 `addEventListener` 的话，
重画出来的新按钮从未被绑定 —— 表现为「第一次点能换，第二次点就没反应」。
但改成委托后监听器会跨导航累积，而委托处理器闭包捕获的 `a` 会是
**第一次绑定时那部作品**：在 B 番详情页点线路会把 A 番的 `activeSourceId` 改掉。
这是数据损坏级的问题，用 `AbortController` 在每次绑定前撤掉上一次的才干净。

> 反向验证量到：撤掉 `abort()` 后**点一次写两次库**。
> 只断言「结果对」抓不到 —— 重复写同一份数据，结果一样对。判据是「点一次后
> 计数器增量恰好为 1」。

**二、WCAG 对比度必须量实际像素，不能拿 `backgroundColor` 算。**
胶囊底色是半透明叠在面板上，`getComputedStyle` 给的 rgba **不是合成结果**。
`tools/verify-pick-source.js` 把那一小块截下来送回页面用 `OffscreenCanvas` 读像素。
量法本身也踩了两个坑：

- **底色不能取分位数。** 小字号文字在整块里只占百分之几的像素，
  3% / 75% 分位会双双落在底色上，算出来必然是 `1.00:1` ——
  看着像「对比度极差」，实际是「根本没分离出文字」。改用「出现次数最多的那一档」当底色。
- **众数法在 pixel 套系下也会被带偏。** 抗锯齿的半调过渡像素数量超过真正的底色像素，
  底色被算成半调、比值接近 1.00，而那张截图里四个黑字清清楚楚、明显过 AA。
  最后用**两端法**（最暗 1% / 最亮 1%），只依赖「最暗的那批一定是笔画」这一条。

**三、`color-mix(..., transparent)` 不能用来「淡化」。** 往 transparent 混是降 alpha，
文字与底色同时变淡，对比度跟着一起塌：实测 0.62 时只有 1.7–2.4:1。
正确做法是往**底色**混（`color-mix(in srgb, var(--text-2) 82%, var(--panel-3))`）——
不透明度不变，只把颜色推向胶囊自己的底。
同理，整颗胶囊加 `opacity:.382` 也是错的：背景一起合成，对比度是平方级下降。

### CDP 环境备忘

写新的浏览器验证脚本时注意（这几条都踩过）：

- `--window-size` 在 `headless=new` 下**会被忽略**，视口只有 500×450。
  元素被排到视口外时 `elementFromPoint` 恒返回 null，测出来的结论全是假的 ——
  必须用 `Emulation.setDeviceMetricsOverride`。
- **CDP 无法模拟 `hover` 媒体特性**。`setTouchEmulationEnabled` /
  `synthesizeTapGesture` 在本机会挂死或报 `Touch points must be between 1 and 16`
  （`maxTouchPoints: 0` 也非法）。可靠做法是注入脚本覆写 `window.matchMedia`，
  让页面「以为」自己无 hover —— 测的是产品代码的分支判断本身。
- 验证脚本被 SIGTERM 打断后 **Edge 进程会残留并占端口**，后续实例起不来
  （表现为脚本静默卡死、连第一行日志都不打）。重跑前先
  `taskkill //F //IM msedge.exe //T` 与 `node.exe`。
- 测 3D 卡片必须等过渡完成（`--dur-slow` ≈ 0.52s → 等 1400ms）。
- 截图缩放会导致视觉误判（曾以为某张卡缺按钮）。以 `getBoundingClientRect` 为准。

## 三条测试纪律

这三条是从踩坑里长出来的，改代码前值得看一眼。

**一、静态断言禁用正则。** JS 字符串里的 `\.` 转义会被吞，正则一旦写坏，
`.test()` 恒返回 `false`，断言**静默失效** —— 比没有断言更危险。
用 `html.indexOf("...") >= 0`，或按花括号配平做结构化解析。

另外，「扫全文找子串」的断言会被注释骗过。验「`.fc-acts` 不再有 `padding-right`」
时搜 `padding-right:44px`，结果注释里就含这个值 → 永远 FAIL。
断言必须限定扫描范围（只扫 CSS 规则、只扫 `DEFAULT_SETTINGS` 区段）或用精确锚点。

**二、静态检查要放在页面加载之前。** 实测：一旦 hover 规则泄漏到触摸端，
jsdom 会在后续交互里陷入死循环，整个测试**静默卡死、连一行断言输出都没有**。
「靠崩溃暴露问题」等于没有测试：不知道是哪一条坏，也不知道是真 bug 还是环境问题。
现在这类检查在加载前拦下并 `process.exit(1)`，会明确报出是哪一条。

**三、验真代码不能自己模拟。** 孤儿清理的断言一开始手写了一遍模拟逻辑，
结果产品里的清理被删也照样通过。凡是「产品会做的计算」，
测试要么调产品函数，要么静态验代码在，别在测试里重写一遍。

还有一条配套的习惯：**改完要反向验证**。注入一处退化，确认新断言真会失败——
不然无法区分「测试有效」和「测试只是恰好通过」。本次清死设置时做了两轮：
把三个键加回 → 挂 3 条；让开机音重新被 `tv_skin` 挡住 → 挂 1 条。

## 已知限制

- **搜索需要联网**，且 Bangumi 在 `file://` 下因 origin 为 null 会被拒。
  可在设置 → 数据源填代理地址，填完点「测试」自检。
  但请先读下面这节 —— 多数公共代理在国内并不好用。
- **`file://` 打开时存储降级**到 localStorage，容量约 5MB。
- **B 站播放**依赖官方 iframe 播放器，番剧需要能访问 `player.bilibili.com`。
  解析失败时会提供跳转官方链接。
- **ECharts 走 CDN**，离线环境下图表降级为文字排行（功能不丢，样式变简）。
- **播放源探测只能确认「服务器有没有响应」，不能确认「能不能播」。**
  浏览器对第三方站点读不到状态码也读不到正文（`no-cors` 下响应不透明），
  所以可达性之外的一切判断（是否需要登录、是否已删、是否被 X-Frame 拒绝）
  都交给用户手动标记。台账因此把「未检测」「网络可达」「被拒绝访问」
  「已标记失效」分成四档 —— 把「没探测过」画成「可用」是在骗用户。
- **线路失效是跨作品的事，但数据仍然按作品存。** 台账只做视图层聚合，
  不合并、不集中存放，所以「批量停用 20 条」也是逐条写回各自的记录。

## 关于 CORS 代理（实测结论，别当银弹）

`data_proxy_url` 只是给「浏览器直连被跨域拦截」留的出口，**不是万能解**。
在无梯子的中国大陆网络下实测15 个常见公共代理（每候选 3 轮，
判据为2xx 且带 `Access-Control-Allow-Origin`）：

| 代理 | 结果 |
|---|---|
| `allorigins.win/raw` | 超时 / 超时 / 超时（偶发单次成功，不可依赖） |
| `allorigins.win/get` | 0/3，且会把响应包成 `{contents:"<原body>"}` |
| `corsproxy.io` | 3/3 返回 **401**，现已要 API Key |
| `api.codetabs.com` | 0/3 超时 |
| `cors.lol` | 3/3 **429** 限流 |
| `corsproxy.xyz` | 3/3 **200 但不带 CORS 头**，浏览器仍拦 |
| `cors-anywhere.herokuapp.com` | 0/3 超时（公共实例早已停用） |
| `cors.eu.org` / `cors.iamnd.eu.org` | **403** |
| `thingproxy` | 域名已失效 |
| `ghfast.top` / `ghproxy.net` | 对 GitHub 200，对其他域名 **403 Invalid input**（只做 GitHub 加速） |

**结论：没有稳定可用的国内公共 CORS 代理。** 免费公共代理的服务器基本在境外，
国内直连就是超时；能通的大多已要 Key 或已关停。

几条因此写进代码的判断：

- **AniList 可直连**（`graphql.anilist.co` 实测 200 + `Access-Control-Allow-Origin: *`），
  通常根本不需要代理。真正需要代理的往往是 Bangumi（`api.bgm.tv` 在部分网络下 TCP 直接不通）。
- **能转发 POST 才算能用**：搜索是 POST，只支持 GET 的代理填进去照样失败。
- **有响应 ≠ 浏览器能读**：缺 CORS 头的代理在 curl 里看着完全正常，页面上照样被拦。
  所以自检单独查 `Access-Control-Allow-Origin`。
- **自动解包壳**：allorigins 的 `/get` 会把响应包成 `{ contents: "<原body 字符串>" }`。
  不解包的话下游读 `data.data`全是 `undefined`，表现成「搜索到 0 条」——
  用户会以为是自己关键词的问题。解包时同时排除 HTML 错误页与 `{ error }`，
  否则代理故障会被伪装成「没搜到」，那是最难查的一类假象。

想要稳定的代理，只能自建：Cloudflare Workers / Vercel / 国内云函数
上放一个十几行的转发，把它的地址填进来，然后用「测试」确认。
`tools/probe-cors-agents.js` 是本节数据的来源，改完网络环境可以自己再跑一遍。

### 五个值得记住的坑

**「一个视图里混着两种行」会一路炸到渲染层。**
台账的「无播放源」那一档构造出的行 `source` 是 `null`（它不是一条线路，是一条待办），
而按状态 / 时间 / 站点排的三个档位都要读 `source` 的字段。
没做兜底时，切到那一档再改排序，整页会显示「页面渲染出错」——
而且只在**这个特定操作顺序**下复现，本地随手点点不出来。
修法是排序层自己把行分成「有线路」与「待办」两拨，
并在 `ledgerKey()` 里对 `source` 为 null 返回空串（空串永远不会出现在选中集里）。

**遍历台账行时，别在里面回头扫整部作品的线路。**
`ledgerDuplicates` 一开始按行遍历、内层扫全作品，同一部作品有几行就被访问几次 ——
表现为「发现 2 条重复」，点去重却只删得掉 1 条。判重是「作品」级的事，遍历就得按作品去重。

**`backface-visibility: hidden` 只管绘制，不管命中测试。**
3D 翻转卡翻过去之后，背面虽然看不见，但**仍然参与命中测试**；
DOM 顺序靠前的正面元素会把背面的点击全部吃掉，冒泡到卡片自身的处理器。
表现是「背面所有按钮行为都一样」——看起来像设计，其实是缺陷。
修法是给不可见那一面显式 `pointer-events: none`。

**空串不能同时表示「无」和「默认值」。** 系列的默认系列 id 是空串，
如果筛选状态也用空串表示「未筛选」，用户选「默认系列」会看到**全部作品** ——
筛选器看着能选，实际不生效。必须三态分开：`null` = 未筛选 / `""` = 只看未归类 /
具体 id = 看某个系列。

**静态托管的根路径只认 `index.html`。** 主文件叫什么名字不要紧，
但站点根没有 `index.html` 就是「404 未找到文件」，报错文案完全不提缺什么文件，
容易误判成 Pages 没启用或分支选错。而且这个问题**在 `file://` 下验不出来** ——
双击打开主文件一切正常，只有部署后才炸。

**本地提交过 ≠ 推得上去。** 在 GitHub 网页端新建 workflow 文件再推本地，
远端就多出一个本地没有的提交，`git push` 直接被拒（non-fast-forward），
报「无法推送 refs 到远端」。这类错误和凭据问题长得完全不一样：
凭据错会明确说 `could not read Username`，被拒则只说「无法推送」，
容易往网络或权限上想。正解是 `git fetch` 后 `git rebase origin/master`（或 `pull --rebase`），
把本地提交挪到远端之上，历史保持线性。

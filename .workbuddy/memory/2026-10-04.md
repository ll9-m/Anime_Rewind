### 2. 放映厅：直接播放外部网站视频
- `EMBED_RULES` 规则表：YouTube（转 nocookie）/ B 站（`player.bilibili.com`）/ Vimeo（三形态）/ iqiyi / generic。
- iframe `sandbox="allow-scripts allow-same-origin allow-presentation ..."` + `referrerpolicy="no-referrer"`；15s 超时兜底诊断；**永远保留「新标签打开」**（iframe 被 X-Frame-Options 拒绝时的唯一出路）。

### 4. 开机音效：三声部怀旧合成（无外部音频文件）
1. **显像管通电**：白噪声 buffer → highpass 1800Hz → lowpass 9000→1200Hz 扫频（0.34s）

### 5. UI 双套系（`data-skin`，与 `data-theme` 正交）
- `UI_SKINS = ["archive","pixel","holo"]`，9 种组合（3 套系 × 3 主题）均测。
- **像素风**（遵循 pixel-dither-web 硬约束）：PICO-8 8 色调色板 + 4×4 Bayer 抖动（`repeating-conic-gradient` 纯 CSS，不为装饰引入 canvas 主循环）+ 0 圆角 + `4px 4px 0` 硬投影 + `steps()` 逐帧 snap。
- **科技风**（用户提供三段示例）：`clip-path` 分层 + `steps(2,end)` 故障按钮、全息开关、conic-gradient 旋转描边输入框。

## 片库空态按钮失效 + 放映厅改造（用户新需求）

用户报两件事：①片库中间「添加第一部动画」点了没反应，右上角「添加新番」正常；
②放映厅要改成截图那样（详情在上、外部播放器在下），去掉语录待机，
播放网址能按番保存、可随时改、记录看到第几集。

### Bug 根因：早退位置错了（且有第二个受害者）

```js
async function libraryAction(act, id, root){
  const a = animeById(id);
  if(!a) return;              // ← 这里
  switch(act){
    case "add": openSearchModal(); break;
```

「添加第一部动画」没有 `data-id` → `animeById(undefined)` 返回 null → **被静默拦死**。
右上角「添加新番」是 `box.innerHTML` 里的另一个节点，走独立绑定路径，所以正常。
**这个「一个能点一个不能点」的不对称，是它难以被发现的根本原因** ——
只测右上角那个按钮就完全发现不了。

**「清空筛选」是同一个 bug 的第二个受害者**（也没有 data-id）。
凡是无参按钮放在「先按参查实体」的函数里，都会中这一枪。

修法：把不依赖作品的动作提到查询之前。
不采用「给按钮塞个假 id」—— 那是让数据迁就 UI。

### 放映厅：删掉待机屏保

用户原话「原来的那个语录待机不要了」。这个需求是合理的：
待机的唯一功能是路过时看一句台词，代价是打开放映厅第一眼看到的
不是「要看什么」而是装饰。

连带删掉**已无调用点的死代码**（留着会让后来者以为屏保还在）：
CRT/现代影院两套皮肤 CSS 约 50 行、`drawSnow()` 50 行、
`standby` 状态对象与 `stopStandby()`、设置页里已失效的三项开关。

**开机音效原本依赖 `settings.tv_skin === "crt"`** —— tv_skin 失去作用对象后，
音效会随一个用户在设置页再也看不到的开关被静默关闭。改为只认 `crt_power_sound`。

未选作品时改为「选一片」网格（卡片带封面 + 进度 + 有无片源）。

### 关键语义修正：片源必须按作品存

原先 `settings.stream_url` 是**全局一份** —— 给 A 番粘的片源会在打开 B 番时
被当成 B 番的片源。用户要的是「不用每次都输入这部番的链接」，
**全局一份在语义上根本满足不了**。改为 `a.streamUrl` + `a.streamEp`。

`settings.stream_url` 保留为「未选作品时的临时片源」，不删以免旧数据失效。

### 集数记录的现实约束

B 站分 P 用 `?p=`，YouTube 用 `&start=`（秒），**两者无法统一换算**。
所以 `applyEpToURL` 只对 B 站写回 `p=`，其余原样返回 —— 改不了总比改错好。
**绝不假装能从播放进度反推集数**，那需要跨域读播放器内部状态，做不到。
于是改成让用户自己声明「看到第几集」，这是诚实的做法。

### 顺带修掉的三个真实缺陷

1. **空值判断顺序错**：`if(!raw || !input.value.trim())` ——
   `applyEpToURL` 对 `javascript:` 伪协议归一化成空串，于是 `!raw` 为真
   但 `input.value.trim()` 为假，条件**放行**了它，提示语还对着非空输入说
   「请先填一个播放网址」。改为先判用户到底填了什么。
2. **提示条元素抓早了**：`#st-status` 只在「未保存」态存在，
   「已保存」态只有 `.note-box`（无 id）。保存过一次后所有后续提示都写进 null ——
   **用户点了没反应却什么也看不到**。改为每次现查。
3. `.stream-note` 的数字用 `var(--accent)`，像素风下 `#ff004d` 配米色只有
   **3.55:1**。改用 `var(--text)`，靠字重强调 —— 颜色不是唯一的信息载体。

### 检查脚本自身的 6 个 bug（本项目第 N 次同源教训）

**这一轮的教训比功能本身更值得记：检查脚本的 bug 会伪装成「产品有缺陷」。**

1. 以为颜色在 `:root` 里 —— 实际全在 `[data-theme="dark|light|glass"]`。
   漏掉 `:root` 让 `--accent` 在 dark 下解析成 null，看着像产品缺变量。
2. 以为存在 `[data-skin="archive"]` 块 —— 档案馆套系不覆写颜色，
   「块不存在」是正常状态，不该判为「令牌无法解析」。
3. 拼接顺序错：`resolve` 取首个匹配，必须「低优先级 → 高优先级」，
   拼反了会读到被覆盖的旧值。
4. **`lastIndexOf(":")` 找键值分界不可靠** —— 一行里常有多处冒号
   （`color:var(--text)` 就有两个），会落在 `var(` 后面把键读成 `"{ color"`。改 `indexOf`。
5. **切分前没剥注释** —— 像素风里
   `/* muted 原为 #5f574f… */ --muted:#3a342e;`
   会让注释和声明粘在一段，键被读成「…-1 压深后升 --muted」，
   解析退回上一作用域的值。症状是「报告某个像素风取值不对」，
   **看着像产品配色问题，实际是解析器没剥注释**。
6. **测试与被测对象脱钩（最严重）**：先写的是「问 `--accent` 是什么」，
   而不是「读 `.stream-note b` 实际用的值」。我改成 `var(--text)` 之后
   脚本毫无反应，仍在报 3.55:1。改为 `resolveRule` 读真实规则，
   并加一条断言钉死「b 必须用 `var(--text)`」——
   否则退化时只有数字变红，看不出是哪条规则退化了。

## 放映厅视觉核查：真实浏览器截图能力打通了

用户这次直接发了一张截图（无文字）。此前记的环境限制是

**这个结论只针对那个插件，不针对 CDP 本身**。本机 Edge 可执行文件存在，

### 关键：注入数据必须走真实路径，不能引用模块作用域标识符

两条正确做法：
1. **就绪判据不能用 `typeof settings`**，同理访问不到，会永远判「未就绪」。
   改用真实副作用：`!!document.querySelector("#view .pick-card")`。
2. **注入走真实用户路径**：写 IndexedDB（库名 `anime-rewind`、表
   `anime/quotes/statuses/assets`、键 `id`）→ `Page.reload` → 点侧栏

   库名/表名/存储键全部取自源码常量（`IDB_NAME`/`LS_SETTINGS` 等），不靠猜。

**通则：测试脚本里出现的 `ReferenceError`，先问「是不是我的作用域假设错了」，
再问「产品是不是坏了」。**

## 修复：番剧播放页无法保存（用户报「连保存都不行」）

用户粘的是 `https://www.bilibili.com/bangumi/play/ep102167`（番剧播放页），

### 根因两层

1. **解析层**：`EMBED_RULES` 的 bilibili 分支只认 `bvid=` / `bilibili.com/video/` /

2. **设计错误（更要命）**：`save()` 里写着
   `if(raw && !resolveEmbed(raw).ok){ showError("网址无法识别，未保存"); return; }`
   —— **保存被绑死在「能否内嵌」上**。用户抱怨的其实是这一条：
   保存一个网址跟能不能在页内播放是两件事。

### CSS：:hover 规则必须包进 @media (hover:hover)
移动端浏览器点完会留下「粘住」的 :hover。若不隔离，静止态卡片会因为
残留 hover 把 pointer-events 交给背面，**手指再点正面就点不动**。
这条 desktop上完全看不出来，只能靠触摸端验证。

### 测试上的三个坑（都花了不少时间）
1. **jsdom 会把 @media (hover:hover) 整块丢掉**（只认有限几种媒体类型），
   遍历 cssRules 恒为空。用它断言会把「规则存在」和「jsdom 不支持」
   混为一谈 —— 将来真删了规则也照样通过（静默失效）。
   解法：读源文本 + 按花括号配平解析出hover 块。
   仍不能只查子串 —— 注释里写一句「包在 @media (hover:hover) 里」就足以骗过断言。
2. **静态检查必须放在页面加载【之前】**。
   实测：hover 规则一旦泄漏，jsdom 会在后续交互里陷入死循环、
   整个 smoke 静默卡死，连一行断言输出都没有。
   「靠崩溃暴露问题」等于没有测试：不知道是哪一条，也不知道是真bug 还是环境问题。
   改成加载前拦下+ process.exit(1)，现在会当场报出「无泄漏」这条失败。
3. **「扫全文找子串」的断言会被注释骗过**。
   例如验「.fc-acts 不再有 padding-right」时，断言搜 `padding-right:44px`，
   结果我自己写的解释性注释里就含这个值 → 永远 FAIL。
   断言必须只扫 CSS 规则或用更精确的锚点。

### CDP / headless 环境备忘（verify-flip.js 已注明）

## GitHub Pages 根路径 404 + 发布托管（同日追加）

### 根因
GitHub Pages 报「404 未找到文件 /该地址配置的站点不支持包含请求的文件」，
报错文案完全不提缺哪个文件，容易误判成 Pages 没启用或分支选错。
实际原因：**静态托管的站点根只解析 `index.html`，而主文件叫 `anime-rewind.html`**。
Pages 配置本身一直是好的。这个问题在 `file://` 下验不出来 —— 双击打开主文件一切正常，
只有部署后才炸，所以之前所有本地测试（含 CDP 浏览器验证）都测不到。

### 修法：跳转页而非复制
加根目录 `index.html` 跳转页，**不**把主文件复制一份改名：
复制会产生两份 1.1MB 独立副本，此后每次改代码都要记得同步两处，
漏同步就产生两个行为不一致的版本，且没有任何机制会提醒。

跳转实现要点：
- 相对路径 `anime-rewind.html`（非绝对路径）—— 站点可能部署在仓库子路径
  `/Anime_Rewind/` 下，相对路径在根部署与子路径部署两种情形都成立。
- `location.replace` 而非 `assign` —— 不往浏览器历史塞一条，用户按返回键不会被弹回。
- `<noscript>` 留兜底链接 —— 纯 meta refresh 在禁用 JS 时无出口。
- 跳转页同样带 author / copyright / license meta，满足 CC BY-NC 4.0 署名要求。
- 配套加 `.nojekyll`：Jekyll 默认把下划线开头的文件当特殊文件处理，禁用避免取不到资源。

### verify-entry.js（新增 9 项）
起本地静态服务，**路径解析规则对齐 Pages 的根行为**（目录请求回落 index.html，缺则 404）。
要点：
- 必须在 `http://` 源下验，不能只 `file://` —— IndexedDB 在两种源下行为不同，
  `file://` 下 origin 为 null 会降级 localStorage，线上不会。
- 含**反向验证**：把 index.html 挪走，根路径必须回 404。
  没有这一步，无法区分「根因修好了」和「这个检查根本没生效」。
- 挪文件用 copy → unlink → 验 → copy 回来，并在 finally 校验文件已恢复，
  避免脚本中途失败把仓库留在坏状态。

### 发布托管
`workbuddy_sites_deploy`，directory 传仓库根，`entryHtml: anime-rewind.html`
（目录里有 index.html 和 anime-rewind.html 两个 html，必须显式指定入口页，
否则服务端无法判断哪个属于这个应用）。
线上：https://anime-rewind.app.workbuddy.host/

`.genie` 标记文件与 `.workbuddy/applications.yaml` 是本地发布元数据，
已加进 `.gitignore`，不进仓库（`git add -A` 会把它们带进去）。

`git push` 报 `could not read Username for 'https://github.com'`：
环境无 GitHub 凭据（`~/.git-credentials` 不存在，gh CLI 未安装）。
提交已在本地（864f7ca、1afb95e），远端需用户在有凭据的环境推送。

## 推送失败排查：远端分叉（非凭据问题）

### 现象与根因
VS Code 弹「无法推送 refs 到远端」。第一反应是凭据缺失，但实际是**历史分叉**：
用户在 GitHub 网页端新建了 `.github/workflows/static.yml`（提交 1818af1），
本地没有这个提交 → non-fast-forward，push 被拒。

**两种失败的报错完全不同，不能混为一谈：**
- 分叉：`无法推送 refs 到远端` / `non-fast-forward` —— 不提凭据二字
- 凭据：`could not read Username` / `unable to get password from user` —— 明确指向认证

分叉那个报错长得像网络/权限问题，正解是 `git fetch` 后 `git rebase origin/master`。
rebase 前需先清未暂存变更（当时是 `.workbuddy/memory/2026-10-04.md` 被纳入版控后又被追加），
否则报 `cannot rebase: You have unstaged changes`。

rebase 后历史线性，`git rev-list --left-right --count origin/master...master` = `0  5`。

### workflow 收敛（用户提交的模板有个坑）
1818af1 用的是 GitHub 官方模板，原样是 `path: '.'`（整个仓库）。三个后果：
1. `tools/` 下 30+ 测试脚本、`.workbuddy/memory/` 内部记录、需求文档全部公开；
2. 每次改测试脚本都触发一次重新部署（artifact 变了但页面没变）；
3. 仓库里任何文件被误提交都直接上线，没有收敛点。

改为显式四项：`anime-rewind.html` / `index.html` / `LICENSE` / `.nojekyll`。
LICENSE 必须在列表里——CC BY-NC 4.0 要求许可全文随作品分发。

### verify-workflow.js（16 项）
清单是 YAML 明文字符串，文件改名时 GitHub 不报错，只在部署日志里留 404，离本地很远。
断言分两类：该在清单里的必须在、不该公开的必须不在。

**踩坑：解析器自身的 bug 伪装成了工作流的 bug。** 首版正则
`/path: \|\n((?:[ \t]+\S[^\n]*\n)+)/` 匹配失败，输出 5 条 FAIL，
第一反应是「工作流写错了」。用 `cat -A` 核对缩进后确认 YAML 正确
（`path: |` + 12 空格），是解析器的问题。改成按行扫、缩进回退即止——
原来的正则若写成匹配到文件尾，会把后面的 `- name: Deploy` 也当成清单项。
**教训：验证脚本报 FAIL 时，先证伪自己的解析器，再怀疑被测对象。**

反向验证：删掉清单里的 index.html 挂 1 条；改回 `path: '.'` 挂 6 条；恢复后 16/16。

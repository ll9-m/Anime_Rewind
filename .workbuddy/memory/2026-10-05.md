# 2026-10-05 工作日志

## 修TV 影院套系的两个可见故障（用户报截图）

用户反馈：① 左侧侧边栏显示不全（截图里品牌只剩 "nime R"、底部只剩一个 "9"）；
② 片库卡片反转后什么也没有了。

上一轮移植 Izuko_TV 时的疏漏。**两个 bug 的共同点：JS 单测全绿，
因为它们都是布局/3D 层面的事，jsdom 测不到。**

### bug 1：侧栏显示不全 —— 三处叠加

1. **收起态用 `opacity:0` 藏文字**（根因）
   `opacity:0` 的元素**照样占布局空间**。而 `.brand` 是 `justify-content:center`，
   居中的是「图标 + 隐藏文字」这个整体（28 + gap + 文字宽 ≈ 140px），
   容器只有 48px → 两侧各溢出 46px 被 `overflow:hidden` 裁掉 →
   图标被推出左缘（实测 left=-63），只剩半个字露在中间。
   上游 Izuko_TV 用 `AnimatedVisibility(expanded)`，语义就是**不参与布局**，
   对应 CSS 的 `display:none`。改掉后连带修好底部 `.side-stat`（同样溢出被裁）。

2. **`flex-basis` 覆盖 `width`，展开从未生效**
   基础规则是 `flex:0 0 var(--sidebar-w)`。flex 容器里 **flex-basis 优先于 width**，
   只改 `:hover` 的 `width:216px` 是完全无效的。必须两处都改。
   （这类「写了 width 却没反应」的表现极具迷惑性——看 CSS 觉得没问题。）

3. **`.nav-item` 写死 32px 方块后没放回**
   展开态文字被塞进 32px 宽的框里逐字换行，容器 overflow 145px。

### bug 2：卡片翻面后空白

```css
[data-skin="tv"] .card:hover .fc-face{ transform:scale(1.06) }  /* 错 */
```

`.fc-face` 是 `.fc-front` 和 `.fc-back` 的**公共类**，而 `.fc-back` 自身带着
`transform:rotateY(180deg)` —— 那行把它**整个覆盖**了。父级 `.card-3d` 已转过180°，
背面失去自身旋转就转到侧面，被自己的 `backface-visibility:hidden` 干掉；正面同理。
**两个面同时不可见= 白卡片，而 DOM 里两个面都还在、样式检查全过。**

修法：正面只缩放、背面在 `rotateY(180deg) scale(1.06)` 的前提下缩放。
顺带删掉 `z-index`—— **`preserve-3d` 元素上 z-index 不参与渲染排序**，
写了以为能抬层、实际无效，是会误导后来者的假代码。

###顺带发现并修掉的三个

- **羽化遮罩盖住自己的文字。** 那个 `::after` 是照搬 Izuko_TV 的
  `TV_RAIL_SCRIM_WIDTH`，前提是「侧栏浮在内容之上」；本项目侧栏是 flex 里的
  独立不透明栏，文字不压在内容上。更糟：它作为最后一个子元素 z 序在内容之上，
  展开动画期间把品牌区和底部信息**洗成残影**。整块删除。
- **`display:revert` 把 `.side-stat` 从 flex 退成 block。**
  revert 回滚到「作者样式」，而本规则的 `display:none` 恰好也在作者样式里，
  最终算出来是 block：数值被挤到第二行，展开态只看得见「收录总数」看不见数字。
  改成显式 `display:flex`。
- **几何常量双源。** CSS 里另写了一份 `--rail-w`/`--tv-bleed`，与 `TV_LAYOUT`
  里的数字各活各的；而原「展开遮罩 180px」那条断言查的是 `TV_LAYOUT.railScrim`
  —— 一个只存在于 JS、**无人使用的死常量**，是恒绿摆设。
  新增 `applyTvTokens()` 让 CSS 变量从 JS 常量派生。

### 验证：新增 `tools/verify-tv-layout.js`（26 项，真实浏览器）

**为什么必须开真浏览器**：jsdom 不做布局也不渲染 3D——
`getBoundingClientRect` 恒返回 0、`backface-visibility`/`perspective` 完全无效。
所以「被overflow:hidden 裁掉」「3D 翻转后两面同时不可见」这类故障，
在单测里**永远是绿的**。用 headless Edge + CDP 量真实几何 + 截图像素统计。

**写像素统计时踩的两个口径错**（都记进脚本注释了）：

1. **阈值必须从实际底色亮度推出，不能写死绝对值。**
   我写死 `46`，而侧栏 `var(--panel)` 在 dark 主题下亮度是 **52**
   → 整块背景被算成「有内容」→ 收起态恒为 `ink=1`。
   这类错跟测试三重编码是同一类：**把环境限制当成产品 bug，或反过来。**
2. **「画面非空」要用相对判据**（翻面后必须明显比翻面前「有东西」）。
   对正面用绝对阈值会恒假红——测试数据常无封面，正面本来就是暗的。

### 一个方法论教训

「CSS 变量与 JS 常量同源」这条断言，**第一版是恒绿的**：
判据写成「跑完后两者相等」，而双源缺陷下两边本来就都是 48，永远相等。
真正能测的是**改掉常量后 CSS 是否跟着变**（临时把 `railCollapsed` 改成 77，
看 `--rail-w` 是不是 77px）。这类「验证同源」的断言必须包含一次变异。

同理，原「展开遮罩 180px」那条断言测的是一个**死常量**——
`TV_LAYOUT.railScrim` 存在但没有任何代码用它。删掉遮罩后它照样绿。
**断言通过的检查项不一定是活代码。**

## 用户问「CORS 代理有没有国内的，不开梯子无法用」→ 实测推翻了前提，改产品而非换地址

### 实测结论（`tools/probe-cors-agents.js`，15 候选 × 3 轮）

判据必须是 **2xx 且带 `Access-Control-Allow-Origin`**，不是「有响应」：

| 代理 | 实测 |
|---|---|
| allorigins /raw | 超时×3（偶发单次成功） |
| allorigins /get | 0/3，且包成 `{contents:"<原body>"}` |
| corsproxy.io | 3/3 **401**（现已要 Key） |
| codetabs | 0/3 超时 |
| cors.lol | 3/3 **429** |
| corsproxy.xyz | 3/3 **200 但无 CORS 头** |
| cors-anywhere.herokuapp | 0/3 超时（公共实例早停用） |
| cors.eu.org / cors.iamnd.eu.org | **403** |
| thingproxy | 域名失效 |
| ghfast.top / ghproxy.net | GitHub 200，其他域名 **403**（只做 GitHub 加速） |

**没有一个稳定可用。** 免费公共代理服务器基本在境外，国内直连即超时。

**关键发现：AniList 可直连**（`graphql.anilist.co` → 200 + `ACAO: *` + 真实数据），
真正需要代理的是 **Bangumi**（`api.bgm.tv` 在本机 TCP 直接不通，
而 gitee/npmmirror/baidu 都 19–46ms 通）。这改变了问题性质：
不是「整个应用都要代理」，而是「只有 Bangumi 这一路需要」。

### 修掉的 3 个真 bug

1. **AniList 写死不代理**（`fetchJSON` 第三参传 `false`）。
   用户填了代理，AniList 被墙时依然用不上 —— 代理只对 Bangumi 生效，
   而这恰是最需要它的那半边。改 `true`。
2. **不处理代理的响应包装层。** allorigins `/get` 返回
   `{ contents: "<原 body 字符串>" }`，`res.json()` 拿到壳对象，
   下游读 `data.data` 全是 `undefined` →界面显示「搜索到 0 条」，
   用户以为是自己关键词的问题。加 `unwrapProxyPayload`，
   **同时排除 HTML 错误页与 `{ error }`** —— 把代理故障解析成
   「空结果」是最难查的一类假象。
3. **自检不能只看「有没有响应」。** 缺 CORS 头的代理在 curl 里
   完全正常，页面上照样被拦。`diagnoseProxy` 分四层报：
   地址格式 / 网络 / HTTP 状态 / CORS 头，另分 401要Key、429限流、5xx 代理故障。

### 探测/测试脚本自身的坑（本轮踩了四个，都记在注释里）

1. **jsdom 没实现 `Response` 构造器**（`typeof Response === "undefined"`）。
   用 `new Response(...)` 做 mock 会在每个场景抛 ReferenceError，
   表现为「全部判成网络层失败」—— 那是在测环境不是测产品。
   改成只含 `status` / `headers.get` / `json` 的鸭子类型。
2. **单次探测会骗人。** allorigins `/get` 超时而 `/raw` 成功，
   同一分钟内同一服务给出相反结论。必须多轮取样。
3. **判据写松等于推荐了坏地址。** 第一版把 401 算成「✔ 稳定」
   （因为带 CORS 头），于是推荐了一个用户填进去必然 401 的服务。
   收紧成「2xx 才算可用」。
4. **链式取值会把测试整体截断。** `unwrap.shell.data.Page.media[0].id`
   在被破坏时抛 TypeError 停在第一条，后面 29 条根本没跑 ——
   看起来「没被抓住」，实际是假阴性。改成先取再判 + try 包裹。
   这条和上一轮 CSS 字符窗口那条是同一个通则：
   **异常终止 ≠ 断言失败，要看它到底跑没跑到后面。**

## 新增「播放源管理」台账页（用户：不好管理哪些能删、哪些失效了）

### 需求背后的判断

用户原话是「加个播放源管理，不然不好管理每部动画的播放源那些可以删，那些失效了等等」。
逐部作品去看线路有两个绕不过的问题：

1. **失效是跨作品的公共事实**。同一个站点挂掉时，库里可能有十几条线路一起失效，
   逐部去发现必然漏掉一半。
2. **删除/停用是批量决策**。「把检测不通的都清掉」在逐部视角下无法表达。

所以做了**跨作品台账**：把 `a.sources` 摊平成 `{ anime, source }` 全局列表。
**台账是视图不是第二份存储** —— 这一条决定了后面所有写操作都必须
定位回原记录，而不是另建一份。

### 数据模型扩展（normalizeSource）

新增三个字段，都只影响管理与筛选，不参与选源质量比较：
- `enabled`（缺省必须 true —— 老数据没这个键，按 falsy 判断会把用户所有线路一次判成停用）
- `note`（备注，最多 200 字）
- `health`（`unknown` / `alive` / `dead` / `blocked` + at + detail）
- 另加`lastUsedAt`，播放时记录

### 关键设计：三种「不确定」不许被画成「确定」

浏览器对第三方站点用 `no-cors`，**读不到状态码也读不到正文**，
唯一能确定的是「响应回来了没有」。所以：

- 探测成功 → `alive`（文案写「网络可达」，不是「可用」）
- 探测失败 → `blocked`（被拒绝/超时/DNS 失败，**绝不写「已失效」**）
- 没探测过 → `unknown`（**不是「可用」**）
- 「已失效」只能由用户手动标记 —— 失效是人的判断，不是探测器的判断

批量探测也**不覆盖**用户手动标的 `dead`：一次网络波动不该抹掉人的结论。

### 「管理」必须真的管用

停用与标记失效同步进两处，否则管理页就是个不生效的标签：
- `filterSources` 三态筛选排除（新增 `disabled` / `dead` 两个原因），
  且**判定顺序在集数/字幕之前** —— 否则同一条线路会先报「集数不匹配」，
  用户改了集数才发现它早就被自己停用了，提示指向的原因不是真正的原因
- `activeSourceOf` 跳过它们（全部不可用时仍返回一条，不返回 null，
  否则详情页显示不出任何线路，用户以为线路被清空了）

### 台账写操作一律走 Repo.put 而非 saveAnime

`saveAnime` 会 `touch()` 改 `updatedAt`。于是「整理一次线路」就能把老作品
顶到「最近添加」最前面。播放记录 `lastUsedAt` 同理。
新增 `persistAnimeQuiet()` 专门干这件事，并在 README 与代码注释里写明原因。

### 本轮修掉的三个真 bug

1. **`ledgerDuplicates` 按行遍历** → 内层又扫整部作品的线路，
   一部作品有几行就被访问几次。表现为「发现 2 条重复」，
   点去重却只删得掉 1 条。改按作品去重遍历。
2. **待办行（`source: null`）一路炸到渲染层**。「无播放源」那一档
   构造的行 `source` 是 null，而按状态/时间/站点排的三个档位都读
   `source` 字段，`ledgerKey()` 也读 `source.id`。
   症状是切到那一档再改排序，整页显示「页面渲染出错」——
   **只在这个特定操作顺序下复现**，本地随手点点不出来。
   修法：排序层分「有线路/待办」两拨；`ledgerKey` 对 null 返回空串
   （空串永远不在选中集里，天然被排除在批量操作外）；
   渲染时选中态判定加 `r.source &&` 前置。
3. **`smoke.js` 的导航项断言写死 7**，且尾部挂着 `|| 长度` ——
   那个兜底让它在导航项为 0（真正该抓的「渲染空了」）时反而通过。
   改成对着 `PAGES.filter(pageModuleEnabled).length` 断言。

### 测试自身踩的坑（本轮 9 条真浏览器断言一度失败）

**5 条是「测试自己制造的前提」**：前一步把某条线路停用了，
后面又写死 id 去取它。测的是前提不是行为。
修法是按当前实际状态取对象（`sourceUsable(r.source)`），
并把「哪几行被动过」显式记下来（`order0`）。
另有一处我误判 `activeSourceOf` 是 bug —— 实际是测试数据
三部作品里那部恰好全不可用，按设计退回全列表是对的；
改用另一部还有可用线路的作品来验「让位」才测到真东西。

`ev` 求值器也返工过：按「有没有 return」决定要不要包一层函数，
漏了「以 ( 开头的 IIFE 里含 return」这种形态，
报出来的是 `Illegal return statement`，完全指不到真因。改成无条件包一层。

## 修台账页三处交互 bug（用户截图：吐司刷屏 / 勾选没勾号 / 缺使用中）

### 1. 吐司刷屏 —— 委托监听器叠了 N 层

`bindLedger(root, all, rows)` 每次 `renderLedger` 都往 root 上挂
`click` / `change` 两个委托监听器，而 `rerenderLedger`走的是
`rerender → renderRoute → page.render(view)` ——
**`#view` 这个节点本身从不替换、只换 innerHTML**。
于是第三次点按钮触发三次，批量操作连着写三次库。

反向验证时量到：**一次点击弹出 90 个吐司**。用户截图右侧那片
「已启用1条线路」就是这么来的。

修法：`root.dataset.ledgerBound` 打幂等标记。

**但只挂一次之后闭包里的 `all` / `rows` / `dupes` 就成了
首次渲染的快照** —— 增删改之后全是旧的。必须改成每次现取：
`rowByKey` 用 `sourceLedger()`，`pick-all` 用 `filterLedgerRows(sourceLedger())`，
批量操作用 `pickedLedgerRows(sourceLedger())`，
`dedupe` 尤其重要：拿上一轮的旧 dupes 列表会**二次删除**。

这条是本轮最值得记住的：**整表重渲的页面 + 委托到常驻容器 = 必须只挂一次，
且挂一次之后闭包里的数据快照全部作废。**

### 2. 勾选框没勾号 —— 状态对但属性没回填

`ledgerRowHTML` 只给 `<tr>` 加了 `is-picked` class，
checkbox 本身**没写 checked 属性**。而每次勾选都整表重渲，
重渲出来的是全新 DOM —— 于是「行高亮着但框里没勾」。

关键点：`box.checked === true` 在重渲后**依然是 true**（用户手动点的，
状态在内存里对），只有量渲染结果才看得出没画勾。
所以断言必须查 `hasAttribute("checked")` 和 `::after` 的计算样式。

**高亮与勾选必须同源**，否则两者各说各话。

### 3. 「使用中」徽标标在已停用线路上 —— 徽标在骗人

`activeSourceOf` 在一部作品全部线路都停用/失效时会退回第一条，
这是**故意的**（免得 activeSourceId 悬空、详情页显示不出线路）。
但`sourceFlags` 直接拿它当「使用中」badge ——
那条线路实际播不了，用户会以为放着不管就能看。

修法：徽标额外要求 `sourceUsable(act)`。
**`activeSourceOf` 保证「有东西可显示」，徽标保证「不撒谎」，两件事必须分开。**
副作用：全停用时「使用中」筛选出 0 行 —— 这是正确行为。

### 测试自身踩的坑

- **CDP 求值器的 IIFE 判定正则漏了箭头函数**：`/^\(?\s*(async\s*)?(\(\)|function)\s*\(/`
  匹配不了 `(() => {...})()`，于是给它外包一层 async 壳 → 返回 undefined。
  报出来的是 undefined，看起来像「功能没生效」，极易误判成产品 bug。
  我在这上面绕了将近半小时，先怀疑产品、再怀疑数据，最后才发现是求值器。
  **教训：一个 harness 反复给出可疑结果时，先怀疑 harness 本身。**
- 截图脚本 `shot-ledger.js` 的 `ev` 把整个表达式包进 `return (...)`，
  传IIFE 进去取不到返回值。修法是让出图脚本复用已验证的求值器。
- **整表重渲会让旧 DOM 引用当场作废**：连续勾选时第二行要用
  `querySelectorAll(...)[1]` 重新查询，事先抓的 `boxes` 数组里
  第二三个元素已脱离文档，dispatchEvent 不再冒泡到 #view。
- 测试步骤间会传递状态：第 6 步把三条线路全停用，第 7 步再筛「使用中」
  必然 0 行。那是数据状态决定的，不是筛选坏了 —— 修法是重置数据。
- 第一次反向验证时 `String.replace` 因换行符（`\r\n`）没匹配上，
  守卫其实还在，于是「吐司只弹一个」照常通过 —— **一个恒真的假绿**。
  改用正则 `\s*` 吞掉换行后才真正撤掉，量到 90 个吐司。
  **反向验证必须确认改动真的生效了，否则测的是原版。**

### 勾号的可见性必须量像素

`input[type=checkbox]` 用 `appearance:none` + `::after` 画对角线，
几何量到（宽高、描边、位置对）不等于人眼看得见。
`tools/verify-pick-contrast.js` 遍历**四套 UI × 明暗主题**，
每种组合量勾号宽高、描边宽度、勾色与底色差异，
再把截图塞回页面用 `OffscreenCanvas` 读像素 ——
**量化后至少 3 种颜色**才算勾真画出来了
（抗锯齿斜边会渲出过渡色，只有 2 种色说明勾压根没画）。

刻意没装 pngjs（为一个断言新增依赖不划算），
`OffscreenCanvas` 浏览器自带，判据一样成立。

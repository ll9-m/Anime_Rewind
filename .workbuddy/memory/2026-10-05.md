# 2026-10-05 工作日志

## 修TV 影院套系的两个可见故障（用户报截图）

用户反馈：① 左侧侧边栏显示不全（截图里品牌只剩 "nime R"、底部只剩一个 "9"）；
② 片库卡片反转后什么也没有了。

上一轮移植 Izuko_TV 时的疏漏。**两个 bug 的共同点：JS 单测全绿，
因为它们都是布局/3D 层面的事，jsdom 测不到。**

### bug 1：侧栏显示不全 —— 三处叠加

1. **收起态用 `opacity:0` 藏文字**（根因）
   `opacity:0` 的元素**照样占布局空间**。而 `.brand` 是 `justify-content:center`，
   居中的是「图标 + 隐藏文字」这个整体（28 + gap + 文字宽 ≈ 140px），
   容器只有 48px → 两侧各溢出 46px 被 `overflow:hidden` 裁掉 →
   图标被推出左缘（实测 left=-63），只剩半个字露在中间。
   上游 Izuko_TV 用 `AnimatedVisibility(expanded)`，语义就是**不参与布局**，
   对应 CSS 的 `display:none`。改掉后连带修好底部 `.side-stat`（同样溢出被裁）。

2. **`flex-basis` 覆盖 `width`，展开从未生效**
   基础规则是 `flex:0 0 var(--sidebar-w)`。flex 容器里 **flex-basis 优先于 width**，
   只改 `:hover` 的 `width:216px` 是完全无效的。必须两处都改。
   （这类「写了 width 却没反应」的表现极具迷惑性——看 CSS 觉得没问题。）

3. **`.nav-item` 写死 32px 方块后没放回**
   展开态文字被塞进 32px 宽的框里逐字换行，容器 overflow 145px。

### bug 2：卡片翻面后空白

```css
[data-skin="tv"] .card:hover .fc-face{ transform:scale(1.06) }  /* 错 */
```

`.fc-face` 是 `.fc-front` 和 `.fc-back` 的**公共类**，而 `.fc-back` 自身带着
`transform:rotateY(180deg)` —— 那行把它**整个覆盖**了。父级 `.card-3d` 已转过180°，
背面失去自身旋转就转到侧面，被自己的 `backface-visibility:hidden` 干掉；正面同理。
**两个面同时不可见= 白卡片，而 DOM 里两个面都还在、样式检查全过。**

修法：正面只缩放、背面在 `rotateY(180deg) scale(1.06)` 的前提下缩放。
顺带删掉 `z-index`—— **`preserve-3d` 元素上 z-index 不参与渲染排序**，
写了以为能抬层、实际无效，是会误导后来者的假代码。

###顺带发现并修掉的三个

- **羽化遮罩盖住自己的文字。** 那个 `::after` 是照搬 Izuko_TV 的
  `TV_RAIL_SCRIM_WIDTH`，前提是「侧栏浮在内容之上」；本项目侧栏是 flex 里的
  独立不透明栏，文字不压在内容上。更糟：它作为最后一个子元素 z 序在内容之上，
  展开动画期间把品牌区和底部信息**洗成残影**。整块删除。
- **`display:revert` 把 `.side-stat` 从 flex 退成 block。**
  revert 回滚到「作者样式」，而本规则的 `display:none` 恰好也在作者样式里，
  最终算出来是 block：数值被挤到第二行，展开态只看得见「收录总数」看不见数字。
  改成显式 `display:flex`。
- **几何常量双源。** CSS 里另写了一份 `--rail-w`/`--tv-bleed`，与 `TV_LAYOUT`
  里的数字各活各的；而原「展开遮罩 180px」那条断言查的是 `TV_LAYOUT.railScrim`
  —— 一个只存在于 JS、**无人使用的死常量**，是恒绿摆设。
  新增 `applyTvTokens()` 让 CSS 变量从 JS 常量派生。

### 验证：新增 `tools/verify-tv-layout.js`（26 项，真实浏览器）

**为什么必须开真浏览器**：jsdom 不做布局也不渲染 3D——
`getBoundingClientRect` 恒返回 0、`backface-visibility`/`perspective` 完全无效。
所以「被overflow:hidden 裁掉」「3D 翻转后两面同时不可见」这类故障，
在单测里**永远是绿的**。用 headless Edge + CDP 量真实几何 + 截图像素统计。

**写像素统计时踩的两个口径错**（都记进脚本注释了）：

1. **阈值必须从实际底色亮度推出，不能写死绝对值。**
   我写死 `46`，而侧栏 `var(--panel)` 在 dark 主题下亮度是 **52**
   → 整块背景被算成「有内容」→ 收起态恒为 `ink=1`。
   这类错跟测试三重编码是同一类：**把环境限制当成产品 bug，或反过来。**
2. **「画面非空」要用相对判据**（翻面后必须明显比翻面前「有东西」）。
   对正面用绝对阈值会恒假红——测试数据常无封面，正面本来就是暗的。

### 一个方法论教训

「CSS 变量与 JS 常量同源」这条断言，**第一版是恒绿的**：
判据写成「跑完后两者相等」，而双源缺陷下两边本来就都是 48，永远相等。
真正能测的是**改掉常量后 CSS 是否跟着变**（临时把 `railCollapsed` 改成 77，
看 `--rail-w` 是不是 77px）。这类「验证同源」的断言必须包含一次变异。

同理，原「展开遮罩 180px」那条断言测的是一个**死常量**——
`TV_LAYOUT.railScrim` 存在但没有任何代码用它。删掉遮罩后它照样绿。
**断言通过的检查项不一定是活代码。**

## 用户问「CORS 代理有没有国内的，不开梯子无法用」→ 实测推翻了前提，改产品而非换地址

### 实测结论（`tools/probe-cors-agents.js`，15 候选 × 3 轮）

判据必须是 **2xx 且带 `Access-Control-Allow-Origin`**，不是「有响应」：

| 代理 | 实测 |
|---|---|
| allorigins /raw | 超时×3（偶发单次成功） |
| allorigins /get | 0/3，且包成 `{contents:"<原body>"}` |
| corsproxy.io | 3/3 **401**（现已要 Key） |
| codetabs | 0/3 超时 |
| cors.lol | 3/3 **429** |
| corsproxy.xyz | 3/3 **200 但无 CORS 头** |
| cors-anywhere.herokuapp | 0/3 超时（公共实例早停用） |
| cors.eu.org / cors.iamnd.eu.org | **403** |
| thingproxy | 域名失效 |
| ghfast.top / ghproxy.net | GitHub 200，其他域名 **403**（只做 GitHub 加速） |

**没有一个稳定可用。** 免费公共代理服务器基本在境外，国内直连即超时。

**关键发现：AniList 可直连**（`graphql.anilist.co` → 200 + `ACAO: *` + 真实数据），
真正需要代理的是 **Bangumi**（`api.bgm.tv` 在本机 TCP 直接不通，
而 gitee/npmmirror/baidu 都 19–46ms 通）。这改变了问题性质：
不是「整个应用都要代理」，而是「只有 Bangumi 这一路需要」。

### 修掉的 3 个真 bug

1. **AniList 写死不代理**（`fetchJSON` 第三参传 `false`）。
   用户填了代理，AniList 被墙时依然用不上 —— 代理只对 Bangumi 生效，
   而这恰是最需要它的那半边。改 `true`。
2. **不处理代理的响应包装层。** allorigins `/get` 返回
   `{ contents: "<原 body 字符串>" }`，`res.json()` 拿到壳对象，
   下游读 `data.data` 全是 `undefined` →界面显示「搜索到 0 条」，
   用户以为是自己关键词的问题。加 `unwrapProxyPayload`，
   **同时排除 HTML 错误页与 `{ error }`** —— 把代理故障解析成
   「空结果」是最难查的一类假象。
3. **自检不能只看「有没有响应」。** 缺 CORS 头的代理在 curl 里
   完全正常，页面上照样被拦。`diagnoseProxy` 分四层报：
   地址格式 / 网络 / HTTP 状态 / CORS 头，另分 401要Key、429限流、5xx 代理故障。

### 探测/测试脚本自身的坑（本轮踩了四个，都记在注释里）

1. **jsdom 没实现 `Response` 构造器**（`typeof Response === "undefined"`）。
   用 `new Response(...)` 做 mock 会在每个场景抛 ReferenceError，
   表现为「全部判成网络层失败」—— 那是在测环境不是测产品。
   改成只含 `status` / `headers.get` / `json` 的鸭子类型。
2. **单次探测会骗人。** allorigins `/get` 超时而 `/raw` 成功，
   同一分钟内同一服务给出相反结论。必须多轮取样。
3. **判据写松等于推荐了坏地址。** 第一版把 401 算成「✔ 稳定」
   （因为带 CORS 头），于是推荐了一个用户填进去必然 401 的服务。
   收紧成「2xx 才算可用」。
4. **链式取值会把测试整体截断。** `unwrap.shell.data.Page.media[0].id`
   在被破坏时抛 TypeError 停在第一条，后面 29 条根本没跑 ——
   看起来「没被抓住」，实际是假阴性。改成先取再判 + try 包裹。
   这条和上一轮 CSS 字符窗口那条是同一个通则：
   **异常终止 ≠ 断言失败，要看它到底跑没跑到后面。**

### 给用户的结论

没有可靠的国内公共 CORS 代理。想要稳定就自建（Cloudflare Workers /
